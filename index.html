About Me

Who I am and what I build.

I'm Arman Christian Mendoza, an AI automation specialist based in the Philippines who designs and ships end-to-end workflows and AI agents for sales, marketing, and operations teams. My work sits at the intersection of no-code automation platforms — n8n, Zapier, and Make.com — and modern LLMs like Claude, GPT, and Gemini. I don't just connect apps; I build systems that automate the repetitive work in sales, finance, recruiting, and operations, and route only the decisions that need a human to the right person.

Outgoing invoices are watched daily, and overdue clients move up a risk-based reminder ladder by email, SMS and call task.

    Automated AR & Payment Follow-Up System (QuickBooks + Twilio + Slack)
    
                        
      
                            
    1. 1Daily Trigger (8am): Pulls open invoices from QuickBooks and reads the Invoices and Clients tabs from Google Sheets, then merges the data into one payload.
      2. 
                            
    2. 2Compute Actions & Content: A Code node evaluates each invoice against the follow-up sequence, decides whether to skip, and determines what content and channel (email/SMS/call) is needed next.
      3. 
                            
    3. 3Skip Logic: A Switch node checks if the invoice should be skipped (e.g. disputed, on a payment plan, or already paid) before any outreach fires.
      4. 
                            
    4. 4Escalation Sequence: Routes to Send Email, Send SMS (Twilio), Needs Call Task, or Needs Internal Alert branches depending on how overdue the invoice is — each branch updates the Clients/Invoices tabs and notifies the AR team on Slack when a human call is needed.
      5. 
                            
    5. 5Monthly Risk Recalculation: A separate monthly trigger pulls all invoices from QuickBooks, merges with client data, recalculates each client's risk & decay score, and updates the Clients tab so the daily sequence always scores against fresh risk data.
      6. 
                        
    
                    
    

    
                        
    AI Recruiting & Hiring System (Zoho Recruit + AI)
    
                        
      
                            
    1. 1Sourcing & Intake: A daily trigger searches job boards & LinkedIn for candidates, while a webhook captures new applications directly. Both paths normalize candidate data and log it to the Applications pipeline sheet.
      2. 
                            
    2. 2AI Screening & Scoring: An AI resume screening agent scores each candidate; a Code node parses the score, and a threshold check (Score ≥ 75) decides whether the candidate advances.
      3. 
                            
    3. 3Advance Path: Qualified candidates are upserted into Zoho Recruit, status set to Interview Scheduled, an interview is booked on Google Calendar, and an AI-drafted interview invite is sent and logged to the Interviews pipeline.
      4. 
                            
    4. 4Below-Threshold Path: Candidates who don't meet the score get an AI-drafted follow-up email instead, logged to the Screened pipeline tab.
      5. 
                            
    5. 5Hiring Decision Webhook: When a decision is made, the workflow drafts and sends an offer or rejection email accordingly, updates status in Zoho Recruit, and logs the outcome to the Offers pipeline.
      6. 
                            
    6. 6Offer Response Webhook: If accepted, sets status to Hired in Zoho Recruit, schedules an onboarding day on Google Calendar, sends a welcome email, and logs to the Hired pipeline. If declined, logs the decline and closes out the record.
      7. 
                        
    
                    
    

    
                        
    AI Voice Appointment Setter (Vapi + Google Calendar)
    
                        
      
                            
    1. 1Webhook: The single entry/exit point — Vapi sends every tool call here as the conversation happens, and this node sends the result back so the AI agent can speak it to the caller.
      2. 
                            
    2. 2Configuration Node: A settings panel controlling timezone, work hours, appointment length, buffer before/after, and how often slots are offered (e.g. every 30 min).
      3. 
                            
    3. 3Route by Tool Name: A switch reads which "tool" Vapi is asking for — checkAvailability or bookAppointment — and sends the data down the matching path.
      4. 
                            
    4. 4Availability Path: Pulls that day's events from Google Calendar, generates all possible time blocks for the workday, removes any that overlap existing events (plus buffer) or are in the past, then formats and returns the remaining slots to Vapi.
      5. 
                            
    5. 5Booking Path: Takes the chosen start/end time and caller details, creates the calendar event directly, and confirms success back to Vapi.
      6. 
                        
    
                    
    

    
                        
    Process Email Invoices with OCR, GPT-4, Slack, QuickBooks and Google Sheets
    
                        
      
                            
    1. 1Intake: Gmail Trigger polls a labeled inbox (AP Inbox) every 5 minutes, pulling in new emails with attachments. Set nodes attach shared config (OCR endpoint, confidence threshold, Slack channel, sheet ID) and derive metadata like sender name, timestamp, and a file hash.
      2. 
                            
    2. 2Text Extraction: An IF node checks the attachment's MIME type. PDFs go to a built-in PDF text extractor; images/scans go to an external OCR API. Both paths merge back into one item.
      3. 
                            
    3. 3AI Structuring: A LangChain agent running GPT-4o extracts invoice fields, line items, totals, and a confidence score per field, outputting structured JSON. A second GPT-4o call repairs the schema if it doesn't parse cleanly.
      4. 
                            
    4. 4Validation & Masking: A Code node independently recalculates totals and flags mismatches against the AI extraction. Another Code node masks PAN/GST/bank account numbers before the data moves downstream.
      5. 
                            
    5. 5Review Gate: If validation failed or any field's confidence is below threshold (default 0.85), the workflow posts a review request to Slack and pauses on a Wait node until resumed. Clean invoices skip straight through.
      6. 
                            
    6. 6Bookkeeping & Audit: A QuickBooks node creates the bill, an audit record (timestamp, QuickBooks ID, validation/confidence results) is appended to Google Sheets, and a final Slack message confirms success.
      7.

    Telegram Crypto Analysis Bot

      2. 
                            
    2. 2Data Fetching & Processing: Requests kline, ticker, and order book data from MEXC in parallel, handles missing records, and computes RSI, EMA, MACD, and Bollinger Bands via JavaScript code nodes.
      3. 
                            
    3. 3Evaluation Pipeline: Compiled indicators are passed to an AI analysis node that checks volume ratios, evaluates signals, and returns a structured JSON verdict.
      4. 
                            
    4. 4Output Delivery: Formats the result into a readable HTML message sent back to the Telegram user.
      5. 
                            
    5. 5Data Logging: Trade signals and technical outputs are recorded into a Google Sheets watchlist.
